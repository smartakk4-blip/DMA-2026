## Что сделано

Одно приложение «Разметки» с главным меню, из которого открывается каждое задание:

- Темы 1–6 — все задания для закрепления (на 8 экранах: по экрану на тему, у темы 5 три экрана)
- 50 практических заданий — каждое отдельной разметкой `p01_…` – `p50_…`

Так как работа про верстку, отдельная Activity на каждый экран не нужна: все разметки показывает одна `ScreenActivity`, а там, где нужно поведение (переключатели, таймеры, выбор фото), оно подключается в `Behaviors.java`.

### Тема 5, задание 5 — почему нельзя RecyclerView внутри ScrollView

1. Оба контейнера прокручиваются по вертикали и спорят за один жест — непонятно, что должно скроллиться.
2. ScrollView измеряет ребенка с неограниченной высотой. Список вынужден создать и отрисовать **все** элементы сразу, а не только видимые — пропадает переиспользование View, главный смысл RecyclerView. На 1000 элементов будет 1000 View, лаги и перерасход памяти.
3. Правильно: один RecyclerView на весь экран, а шапку и подвал сделать отдельными типами элементов (или ConcatAdapter). Списки с **разным** направлением (горизонтальная карусель в вертикальном экране) — это нормально.

## Тема 7: Overdraw

- Белый фон рисует только окно (`windowBackground`). Если у экрана свой цветной фон, `ScreenActivity` отключает фон окна — пиксель не закрашивается дважды.
- В практике 50 у корня, ScrollView и BottomBar фона нет вообще, нижний бар отделен линией 1dp вместо тени.
- Android Lint сначала нашел 44 места с возможным Overdraw и вложенные веса (`NestedWeights`) в шапке профиля — всё исправлено, в отчете Lint 0 ошибок.
- Проверка на эмуляторе в режиме «Отладка GPU-перерисовки» — скриншот ниже: страница товара в основном синяя (1 перерисовка) и зеленая (2). Розовым (3) отмечены только иконки тулбара, которые лежат на градиенте поверх фото, и текст на кнопке. Красных зон (4 и больше) нет.

## Вывод

Разобрался, когда какой контейнер выбирать: LinearLayout — для простых рядов и пропорций через веса, FrameLayout — для слоев и оверлеев, RelativeLayout — для небольших блоков с привязкой к соседям, ConstraintLayout — для сложных экранов без вложенности (цепочки, барьеры, направляющие, пропорции). Научился собирать экраны из частей через include/merge и откладывать загрузку редких экранов через ViewStub, а также проверять верстку на лишнюю перерисовку и вложенные веса.
